# pw-artillery

TypeScript project for DemoBlaze that combines:

- Playwright functional UI tests
- Artillery browser-based load/performance tests (using the Playwright engine)

Target site: `https://www.demoblaze.com`

## Artillery Docs

- Getting started: <https://www.artillery.io/docs/get-started/get-artillery>
- Playwright engine: <https://www.artillery.io/docs/reference/engines/playwright>
- Test script phases: <https://www.artillery.io/docs/reference/test-script#load-phases>
- Metrics reference: <https://www.artillery.io/docs/reference/artillery-metrics-reference>

## Quick Start

```bash
npm install
npx playwright install

# Functional tests (Chromium)
npm run func:test:report:cloud

# Warm-up load test
npm run arty:load:test
```

## Prerequisites

- Node.js 18+
- npm

Optional `.env` for Artillery Cloud reporting:

```bash
ARTILLERY_CLOUD_API_KEY=your_api_key
```

## NPM Scripts

### Functional (Playwright)

- `npm run func:test:report:cloud` run Playwright tests on Chromium (`tests/e2e`)
- `npm run func:test:headed` run Chromium tests in headed mode
- `npm run func:test:ui` open Playwright UI mode for Chromium tests
- `npm run func:report` run Chromium tests then open Playwright HTML report

### Load/Perf (Artillery + Playwright engine)

- `npm run arty:load:test` run warm-up load scenario (`tests/load/homePage.load.spec.ts`)
- `npm run arty:load:report` run warm-up load scenario and record to Artillery Cloud
- `npm run arty:perf:test` run multi-phase performance scenario (`tests/perf/homePage.perf.spec.ts`)
- `npm run arty:perf:report` run performance scenario and record to Artillery Cloud

### Combined

- `npm run func:report:then:arty:load:report` run Playwright functional tests, then Artillery load test with Cloud recording

## Test Suites

### `tests/e2e/homePage.spec.ts`

Functional coverage includes:

- homepage title and URL
- navigation visibility
- category sidebar visibility
- product list visibility
- category filtering (`Phones`, `Laptops`, `Monitors`)
- product detail navigation
- login and sign-up modal visibility
- carousel visibility

### `tests/load/homePage.load.spec.ts`

Short warm-up load scenario:

- phase: 10s, `arrivalRate: 1`, `maxVusers: 10`
- user flow: open homepage, open/close login modal, browse Phones, open product page, return
- ensure thresholds:
- `http.response_time.p95 < 3000`
- `browser.page.TTFB.https://www.demoblaze.com/.p95 < 1800`
- `browser.page.FCP.https://www.demoblaze.com/.p95 < 500`
- `browser.page.LCP.https://www.demoblaze.com/.p95 < 3500`
- `vusers.failed == 0`

### `tests/perf/homePage.perf.spec.ts`

Longer performance scenario:

- 4 phases: Warm-up, Ramp-up, Sustained load, Cool down
- configured with `workers: 8`
- stricter/expanded ensure thresholds including p95/p99 response times and web vitals

## Configuration Notes

- `playwright.config.ts`: e2e test dir is `tests/e2e`, reporter is `@artilleryio/playwright-reporter`, projects include desktop and mobile profiles, traces are enabled.
- `tsconfig.json`: `target` is `ES2022`, `module` is `commonjs`, and strict mode is enabled.

## Page Object

`src/HomePage.ts` contains reusable locators and actions for DemoBlaze homepage interactions used across all suites.
